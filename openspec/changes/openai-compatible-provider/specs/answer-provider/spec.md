## ADDED Requirements

### Requirement: OpenAI-compatible provider selection
The value `openai-compatible` SHALL select a provider that calls an endpoint implementing the OpenAI-style chat completions API, in addition to `claude` and `ollama`; any other value SHALL still be rejected as a configuration error that names the allowed values.

#### Scenario: Hosted provider selected
- **WHEN** the configured provider is `openai-compatible` and base URL, key and model are set
- **THEN** answers are generated by that endpoint

#### Scenario: Unknown provider
- **WHEN** the configured provider is none of `claude`, `ollama` and `openai-compatible`
- **THEN** answer generation fails with a configuration error and no request is sent

### Requirement: Hosted provider configuration
The OpenAI-compatible provider SHALL read base URL, API key and model name from configuration and SHALL have no default for any of them.

#### Scenario: Setting missing
- **WHEN** the provider is selected and the base URL, the key or the model is not configured
- **THEN** answer generation fails with a configuration error naming the missing setting and no request is sent

### Requirement: Hosted calls go only to the configured endpoint
The OpenAI-compatible provider SHALL send question and document text only to the configured base URL, and the README SHALL state that this sends that text to a third party.

#### Scenario: Request target
- **WHEN** a question is answered with this provider
- **THEN** every request is made to the configured base URL and to no other host

### Requirement: The key is never disclosed
The API key SHALL be sent only to the configured base URL and SHALL NOT appear in logs, error messages, API responses, eval output or result files.

#### Scenario: Request fails
- **WHEN** a request to the endpoint fails
- **THEN** no log line, response or result file contains the key

### Requirement: Requests are spaced
The OpenAI-compatible provider SHALL wait at least a configured interval between requests, SHALL widen that interval after a rate-limited answer, and SHALL narrow it again, down to the configured one, after successful requests.

#### Scenario: Rate limited
- **WHEN** the endpoint answers "too many requests"
- **THEN** later requests are spaced further apart until successes shrink the spacing again

### Requirement: Transient failures are retried with backoff
The OpenAI-compatible provider SHALL retry transient failures (rate-limited, overloaded or temporarily failing answers, a dropped connection, a timeout) a bounded number of times, with exponentially growing, randomly jittered waits that are never shorter than the wait the server asked for.

#### Scenario: Overload then recovery
- **WHEN** the endpoint answers "temporarily unavailable" and a later attempt succeeds within the bound
- **THEN** the answer is produced from the successful attempt

#### Scenario: Server asks for a wait
- **WHEN** the endpoint states how long to wait before retrying
- **THEN** the next attempt is not made sooner than that

#### Scenario: Limit persists
- **WHEN** the endpoint keeps failing transiently beyond the bound
- **THEN** the call fails, the response is a refusal, and the failure is counted as a model error in the eval

### Requirement: Permanent errors fail fast
The OpenAI-compatible provider SHALL NOT retry errors that retrying cannot fix, such as an unknown model or an invalid key, and SHALL abandon a request that gets no answer within a time limit.

#### Scenario: Unknown model
- **WHEN** the endpoint answers that the model is not available
- **THEN** the call fails immediately without retries

### Requirement: Results record the endpoint
Every answer eval result produced with this provider SHALL record the provider, the model and the endpoint host.

#### Scenario: Hosted run
- **WHEN** the answer eval runs with the OpenAI-compatible provider
- **THEN** the result file states provider `openai-compatible`, the model name and the host
- **AND** the README table row names the same provider, model and host and does not present the result as Claude's
